# 読書感想文作成・推敲テンプレート

中学生・高校生などの読書感想文を、**対話型AI + ファイルを扱えるAI環境 + GitHub**で作成・推敲するためのテンプレートです。

本テンプレートは、特定のAIサービスやAIコーディングエージェントに依存しない構成になっており、以下のような環境で利用できます。

### 対応しているAI環境

* **ChatGPT**
* **ChatGPT Projects**
* **Codex**
* **Cursor**
* **Claude**
* **Claude Projects**
* **Claude Code**
* **その他、プロジェクト内のMarkdownファイルを読み書きできるAI環境**

また、AI環境を組み合わせて使用することもできます。

たとえば、**ChatGPTで読書感想文の内容を相談・レビューし、Cursor・Claude Code・Codexなどのファイル編集可能なAI環境でMarkdownファイルを更新する**といった使い方ができます。

AI環境によって利用できる機能や操作方法は異なりますが、本テンプレートでは、AI環境固有の設定ではなく、**README.md、各種Markdownファイル、および `AI/` フォルダ内のルールを基準として作業します。**

このRepositoryをForkして、自分の読書感想文プロジェクトとして使用します。

Gitを使わなくても、CloneまたはZIP展開したフォルダを開くだけで使用できます。

## おまけ

このテンプレートには、読書感想文の作成・推敲を補助するためのおまけがあります。

- **おまけ1：本専用の読書中質問リストを作成するプロンプト**
  読む本の情報を入力すると、その本の内容に合わせた「読書中に答える質問リスト」をChatGPTに作成させます。
  本を読みながら、印象に残った場面、感じたこと、考えたこと、登場人物について思ったこと、自分の経験とのつながりなどを、自分の言葉で記録するために使用します。

- **おまけ2：本の挿絵を作る画像生成プロンプト**
  読んでいる本の特定の場面を、読書感想文プロジェクト用の挿絵として画像生成するためのプロンプトです。
  本の内容と「この場面まで読んだ」という範囲を指定し、まだ読んでいない部分のネタバレを避けながら、指定した場面を画像として表現します。

# まずやってみる

文章を全部読む必要はありません。まず以下だけ実行してください。

## 1. GitHubでFork

このRepositoryをGitHubで**Fork**します。

GitHubやGitを使わない場合は、RepositoryをZIPでダウンロードして使用しても構いません。

## 2. CloneまたはZIP展開

Gitを使う場合は、ForkしたRepositoryをPCにCloneします。

Gitを使う場合は、作業の前後など、区切りのよいタイミングでコミットしておくことをおすすめします。バックアップとして利用でき、変更内容も差分で確認できます。

Gitを使わない場合は、RepositoryをZIPでダウンロードして展開します。

## 3. プロジェクトフォルダを開く

Cloneまたは展開したフォルダを、お使いのエディタまたはAI環境で開きます。

## 4. 初期ファイルを確認する

ZIP展開後、次のファイルとフォルダが最初から存在します。

```text
PROJECT_INFO.md
QUESTIONNAIRE.md
STUDENT_NOTES.md
ANALYSIS.md
AI/
```

AI作業ファイル（DRAFT / REVIEW / USER_REQUEST）の配置場所と運用ルールは、`AI/README.md` を参照してください。

## 5. 本の情報を入力する

`PROJECT_INFO.md`を開き、必要な情報を入力します。

```text
本の題名:

著者:

読む人の学年または年齢:

目標分量:

言語:

学校・コンクール等:

その他の条件:
```

## 6. 質問に答える

`QUESTIONNAIRE.md`を開き、質問に自分の言葉で回答してください。

短いメモや箇条書きでも構いません。

この段階では、完成した読書感想文を書く必要はありません。

## 7. 本人の材料を整理する

回答ができたら、AI環境に次のように指示します。

```text
PROJECT_INFO.mdとQUESTIONNAIRE.mdを読み、本人の回答をSTUDENT_NOTES.mdに整理してください。
```

AIは本人が提供した情報を整理します。

本人が提供していない経験、感情、意見などを追加してはいけません。

## 8. 最初のドラフトを作る

AI環境に次のように指示します。

```text
PROJECT_INFO.md、QUESTIONNAIRE.md、STUDENT_NOTES.mdを読み、
ANALYSIS.mdとAI/DRAFT_01.mdを作成してください。
```

AIが読書感想文を書くための材料を整理し、最初の原稿 `AI/DRAFT_01.md` を作成します。

以後、ドラフトは番号付きファイルで管理します。

```text
AI/DRAFT_01.md
AI/DRAFT_02.md
AI/DRAFT_03.md
...
```

既存のDRAFTは上書きしません。

原稿用紙のページ区切りは、DRAFT内で次の形式を使用します。

```markdown
<!-- PAGE: 01 -->

1ページ目の文章

<!-- PAGE: 02 -->

2ページ目の文章
```

ページごとに別ファイルを作る必要はありません。

ここまでが初期準備です。

```text
PROJECT_INFO.md
QUESTIONNAIRE.md
        ↓
STUDENT_NOTES.md
        ↓
ANALYSIS.md
AI/DRAFT_01.md
```

# 9. ChatGPTでDRAFTをレビューする

ここからは、ChatGPT等を使って現在のDRAFTをレビューします。

ファイル添付は使用せず、**レビュー用プロンプトをコピーした直後に、レビューするDRAFT本文をコピーします。**

## 9-1. レビュー用プロンプト

以下のプロンプトをそのままChatGPTに貼り付けてください。

**プロンプトを変更する必要はありません。**

```text
以下の読書感想文をレビューしてください。

目的:
PROJECT_INFO.mdに記載された学年・年齢の生徒が、自分自身の考えや経験をもとに書いた読書感想文として、内容、構成、具体性、読みやすさ、本人らしさを改善するためのレビューをしてください。

重要な条件:

- 本人が提供していない経験、感情、記憶、意見を作らない。
- 本人が書いていない考えを、本人の意見として補完しない。
- 本の内容について不確かなことを事実として追加しない。
- 不明な情報を推測で補わない。
- 大人の文章に書き換えることを目的にしない。
- PROJECT_INFO.mdに記載された学年・年齢として不自然に大人びた表現を避ける。
- 幼すぎる文章にも、過度に難しい評論文にも変えない。
- 本人の文章の良さや個性を残す。
- あらすじの説明が多すぎないか確認する。
- 本人だから書ける具体的な経験、感情、考えが表れているか確認する。
- 「この本を読んで自分が何を考えたのか」が中心になっているか確認する。
- PROJECT_INFO.mdに記載された分量・文字数・原稿用紙枚数などの条件を考慮する。
- 完成稿を全面的に書き直さない。
- 改善候補を具体的に示す。
- 各改善候補は、ユーザーが採用するかどうか判断できる形にする。
- 修正案は本人がすでに提供している材料の範囲を超えない。
- 本人による追加情報が必要な場合は明記する。
- レビュー結果は、必要な変更だけをUSER_REQUESTに記録しやすい形式にする。
- レビュー結果そのものは次のDRAFT作成の入力資料ではない。
- ユーザーが採用していない提案を次のDRAFTへ反映してはいけない。

レビュー形式:

# レビュー

## 良いところ

既存文章の良い点を具体的に説明してください。

## 改善したいところ

改善したほうがよい点を説明してください。

## 変更候補

各変更候補を独立した項目として記載してください。

### CHANGE-01

対象:
どの部分を変更する提案なのか。

問題:
何を改善するのか。

変更案:
具体的な修正方法。

理由:
なぜこの変更が有効なのか。

注意:
本人の追加情報が必要なら、そのことを明記してください。

### CHANGE-02

同じ形式で続けてください。

## 本人が追加で考える必要があること

AIだけでは決められない内容を列挙してください。

## 次の推敲で優先すること

変更候補の中から優先度が高いものを説明してください。

重要:
レビュー対象の文章そのものを全面的に書き直した完成稿は作らないでください。

以上がレビュー用プロンプトです。

この後に、今回レビューするDRAFT本文をそのまま貼り付けてください。
```

## 9-2. DRAFT本文を貼り付ける

9-1のプロンプトを貼り付けた直後に、今回レビューするDRAFT本文をそのまま貼り付けます。

DRAFT本文には、ファイル名などを追加する必要はありません。

レビュー結果には複数の `CHANGE-XX` が含まれる場合があります。

**この段階では、AIに採用する変更を決めさせません。**

# 10. REVIEWを保存する

ChatGPTのレビュー結果を、そのまま `AI/REVIEW_XX.md` として保存します。

例えば、

```text
AI/DRAFT_01.md
    ↓
AI/REVIEW_01.md
```

です。

`AI/REVIEW_XX.md` は**AIの提案を保存するファイル**です。

ユーザーが採用を決めていない提案は、次のDRAFTに反映されません。

---

# 11. 採用する変更をUSER_REQUESTにする

`AI/REVIEW_XX.md`を確認し、次のDRAFTに反映したい変更だけを `AI/USER_REQUEST_XX.md` に記録します。

例えば、

```text
AI/REVIEW_01.md
    ↓
ユーザーが変更を選択
    ↓
AI/USER_REQUEST_01.md
```

です。

レビュー全体をコピーする必要はありません。

`USER_REQUEST`には、**ユーザーが実際に実行してほしい変更だけ**を書きます。

例えば、

```markdown
# User Request

対象ドラフト: AI/DRAFT_01.md
作成するドラフト: AI/DRAFT_02.md

## 採用する変更

### 1

第2段落について、現在書かれている経験を使って、なぜそう感じたのかを1〜2文追加する。

新しい体験、感情、記憶、意見は追加しない。

### 2

第3段落を少し短くする。

ただし、現在の「〜と思った」という表現は残す。
```

採用しない変更は記録しません。

`AI/USER_REQUEST_XX.md`は、AIレビューの保存場所ではなく、**次のDRAFTに対するユーザーの実行指示**です。

---

# 12. AI環境で次のDRAFTを作成する

`AI/USER_REQUEST_XX.md`ができたら、AI環境で次のDRAFTを作成します。

ここでは、現在のDRAFTとUSER_REQUESTだけを入力として使用します。

```text
現在のDRAFT
+
USER_REQUEST
↓
次のDRAFT
```

例えば、

```text
AI/DRAFT_01.md
+
AI/USER_REQUEST_01.md
↓
AI/DRAFT_02.md
```

です。

AI環境には、**最初の3行だけ、その回で使用するファイル名に変更して指定します。**

```text
draft_base=AI/DRAFT_01.md
user_request=AI/USER_REQUEST_01.md
draft_out=AI/DRAFT_02.md
```

続けて、以下をそのまま入力（コピペ）します。

```text
上記2つの入力ファイルを使用し、user_requestの指示をdraft_baseに反映してdraft_outを作成してください。

使用してよい情報は、draft_baseとuser_requestに含まれる情報だけです。他のファイル、過去のレビュー、会話履歴、一般的な知識、推測などから新しい情報を追加してはいけません。

既存ファイルは変更・上書きせず、draft_outだけを新規作成してください。user_requestに明記されていない内容上の変更は行わないでください。

本人が提供していない経験・感情・意見・記憶を追加しないでください。本の内容について不確かなことを推測で補わないでください。材料が不足している場合も勝手に補完しないでください。

指定された変更を実行するために必要な範囲で、文章の接続、文法、表現を調整して構いません。ただし、意味や内容を変更したり、指定されていない改善を加えたりしないでください。

元の文章の内容、本人らしい表現、良さをできるだけ維持し、必要な箇所だけを変更してください。ページ区切りの形式も維持してください。

指示を安全かつ正確に実行できない変更がある場合は、その変更を行わず、理由を報告してください。
```

AIが行う処理は、

```text
draft_base
+
user_request
        ↓
draft_out
```

だけです。

次の回は、最初の3行だけを変更します。

```text
draft_base=AI/DRAFT_02.md
user_request=AI/USER_REQUEST_02.md
draft_out=AI/DRAFT_03.md
```

**重要なのは、AIが参照する入力ファイルを `draft_base` と `user_request` の2つに限定していることです。**

`AI/REVIEW_XX.md`、その他のプロジェクトファイル、過去の会話、一般知識などは入力として使用しません。

**`AI/REVIEW_XX.md`から直接DRAFTを作らないことが重要です。**

# 推敲ループ

以後は次の流れを繰り返します。

```text
AI/DRAFT_01.md
    │
    │ ChatGPTでレビュー
    ↓
AI/REVIEW_01.md
    │
    │ ユーザーが採用する変更を選択
    ↓
AI/USER_REQUEST_01.md
    │
    │ AI環境で推敲
    ↓
AI/DRAFT_02.md
```

次の回：

```text
AI/DRAFT_02.md
    │
    ↓
AI/REVIEW_02.md
    │
    ↓
AI/USER_REQUEST_02.md
    │
    ↓
AI/DRAFT_03.md
```

さらに：

```text
AI/DRAFT_03.md
    │
    ↓
AI/REVIEW_03.md
    │
    ↓
AI/USER_REQUEST_03.md
    │
    ↓
AI/DRAFT_04.md
```

役割は次のように分離されます。

```text
REVIEW
    = AIの提案

USER_REQUEST
    = ユーザーが採用した変更

DRAFT
    = 採用した変更を反映した文章
```

この分離により、AIがレビュー内容から勝手に変更を採用することを防ぎます。

---

# 13. 推敲を終了する

文章が十分に良くなったと思ったところで終了します。

最後のDRAFTを必ず採用する必要はありません。

例えば、

```text
AI/DRAFT_01.md
AI/DRAFT_02.md
AI/DRAFT_03.md
AI/DRAFT_04.md
```

があれば、それらを比較して最も良いものを完成稿として使用できます。

推敲によって文章が悪くなった場合は、前のDRAFTを採用して構いません。

すべてのDRAFTを残しておけば、文章の変化を後から確認できます。

また、

```text
AI/REVIEW_XX.md
```

にはAIの提案、

```text
AI/USER_REQUEST_XX.md
```

にはユーザーが採用した変更、

```text
AI/DRAFT_XX.md
```

にはその結果が残ります。

つまり、

```text
AIが何を提案したか
        ↓
ユーザーが何を採用したか
        ↓
文章がどう変わったか
```

を確認できます。

Gitを使わなくても、ファイルだけで推敲履歴を管理できます。

# ファイル構成

初期状態：

```text
PROJECT_INFO.md
QUESTIONNAIRE.md
STUDENT_NOTES.md
ANALYSIS.md
AI/
```

推敲を進めると：

```text
PROJECT_INFO.md
QUESTIONNAIRE.md
STUDENT_NOTES.md
ANALYSIS.md

AI/
├─ DRAFT_01.md
├─ REVIEW_01.md
├─ USER_REQUEST_01.md
├─ DRAFT_02.md
├─ REVIEW_02.md
├─ USER_REQUEST_02.md
└─ ...
```

| ファイル | 役割 |
|---|---|
| `PROJECT_INFO.md` | 本・学年・分量・課題条件など |
| `QUESTIONNAIRE.md` | 本人から材料を引き出す質問 |
| `STUDENT_NOTES.md` | 本人が提供した材料の整理 |
| `ANALYSIS.md`        | 初回DRAFTを作成するための分析・構成 |
| `AI/DRAFT_XX.md` | その時点の読書感想文 |
| `AI/REVIEW_XX.md` | AIによるレビュー・改善提案 |
| `AI/USER_REQUEST_XX.md` | ユーザーが採用した変更の実行指示 |
| `AI/README.md` | AI作業領域・推敲フローの利用ルール |

特に重要なのは次の関係です。

```text
REVIEW
AIの提案
    ↓
ユーザーが判断
    ↓
USER_REQUEST
採用した変更
    ↓
AIが実行
    ↓
DRAFT
```

# 重要なルール

詳細なAI作業ルールは `AI/README.md` を参照してください。

1. 既存のDRAFTを上書きしない。
2. 既存のREVIEWを変更・上書きしない。
3. 既存のUSER_REQUESTを変更・上書きしない。
4. 新しいDRAFTは新しいファイルとして作成する。
5. 次のDRAFTは、前のDRAFTとUSER_REQUESTだけを基に作成する。
6. REVIEWをDRAFT作成の入力として使用しない。
7. AIレビューの提案をユーザーの確認なしに採用しない。
8. USER_REQUESTに書かれていない変更を追加しない。
9. 本人が提供していない経験、感情、意見、記憶を作らない。
10. 本の内容について不確かなことを推測で補わない。
11. 材料が不足している場合はAIが勝手に補完しない。
12. 元の文章の良さや本人らしい表現を必要以上に変更しない。
13. ページ区切りの形式を維持する。
14. REVIEWとDRAFTの対応関係は、保存時のファイル名によって管理する。
15. USER_REQUESTには対象DRAFTと作成するDRAFTを明記する。
16. AIに「最新ファイル」を自動判定させず、使用するファイル名を明示する。
17. AIの提案とユーザーの意思決定を別ファイルで管理する。

# おまけ：本別の質問リストをつくるためのプロンプト

このテンプレートは、読書感想文を書く前に、読んだ本について「自分が何を感じたか・何を考えたか」を思い出すための質問リストをChatGPTに作らせるために使用します。

**注意：この質問リストには、本の登場人物、出来事、場面、テーマなど、本の内容に関する質問が含まれる場合があります。まだ読んでいない部分についての質問が表示されると、ネタバレになる可能性があります。これから読む本について質問リストを作成する場合は、注意してください。**

1. 以下のテンプレートに、本の情報を入力します。
   - PROJECT_INFO.mdから「本の題名」「著者」「学年・年齢」「目標分量」などをコピーしても構いません。
   - PROJECT_INFO.mdがまだない場合は、このテンプレートに直接入力します。

2. テンプレート全体をChatGPTに貼り付けて実行します。

3. ChatGPTが、その本の内容に合わせた質問リストを作成します。
   一般的な「面白かったですか？」だけではなく、登場人物、出来事、印象に残った場面、読んでいる途中の感情、読後に考えたことなど、本特有の内容を思い出せる質問を作ります。

4. 作成された質問リストを、実際に本を読みながら使います。
   本文を読み返したり、気になった場面でメモしたりしながら、自分の言葉で回答します。

5. 回答した内容は、後でQUESTIONNAIRE.mdやSTUDENT_NOTES.mdを作成するときの材料として使用できます。

重要:
このプロンプトは読書感想文そのものを書かせるためのものではありません。
「本人が自分の経験・感情・考えを思い出すための質問を作る」ことが目的です。

また、ChatGPTが本の内容を勝手に想像して質問を作らないように、入力した本の情報だけでは判断できない内容については、必要に応じて確認質問をさせる構成にしておくと安全です。

```text
# 読書中質問リスト作成用プロンプト

以下の情報をもとに、この本を実際に読みながら回答できる「本専用の質問リスト」を作成してください。

目的は、読書感想文を書くために、読んでいる本人の考え、感情、気づき、疑問、経験との結びつきなどを記録しておくことです。

質問は、本の内容を確認するための読解テストではなく、読書感想文の材料を本人自身から引き出すためのものにしてください。

## 本の情報

以下に `PROJECT_INFO.md` の該当部分を貼り付けます。
または、ここに直接入力します。

## 質問リスト作成の条件

- 上記の本にできるだけ特有の質問を作ってください。
- 本の登場人物、出来事、場面、テーマ、設定、著者の表現など、実際にその本を読むことで答えられる質問を中心にしてください。
- 単なる「この本を読んでどう思いましたか？」のような、どの本にも使える質問だけで構成しないでください。
- ただし、本専用の質問だけでは本人の感想や経験を十分に引き出せない場合は、一般的な質問も必要な範囲で追加してください。
- 質問は「正解を答える問題」ではなく、本人が自分の言葉で答えられる質問にしてください。
- 本の内容を詳しく説明させることを目的にしないでください。
- あらすじを大量に書かせる質問は避けてください。

- 本人が特に印象に残った場面を見つけられるようにしてください。
- 登場人物への共感、反感、疑問、納得できなかった点なども引き出してください。
- 読む前と読んだ後で考えが変化した場合、その変化を記録できるようにしてください。
- 本のテーマについて本人自身がどう考えたのかを引き出してください。
- 本の内容と本人自身の学校生活、家庭生活、友人関係、趣味、体験などが結びつく可能性がある場合は、その関連を考えられる質問を入れてください。
- ただし、本人に特定の経験があることを前提にしないでください。
- 「こういう経験をしたはず」と誘導する質問は禁止します。
- 本人が経験していないことを作らせる質問は禁止します。
- 本人が答えにくい質問を大量に作らず、実際に読書中に使いやすい数にしてください。
- 同じ内容を別の表現で繰り返す質問は避けてください。
- 中学生・高校生が自分で読んで理解できる自然な日本語にしてください。
- 質問そのものが難しい評論文のようにならないようにしてください。
- 読書感想文の完成文を書かせる質問にはしないでください。
- 回答は短いメモや箇条書きでも答えられるようにしてください。
```
